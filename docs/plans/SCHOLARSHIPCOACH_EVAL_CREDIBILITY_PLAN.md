## Why this plan exists

A senior-DS review of the project found the engineering strong but identified two
**methodological circularity problems** that an interviewer would probe within minutes:

1. **Proxy-label circularity.** Relevance labels (`src/eval/relevance.py`) are built from
   `keyword_overlap` and `text_sim` — the same signals Stage 2 scores on — and then
   `tune_weights.py` optimizes NDCG against those labels. The headline "0.29 → 0.61 NDCG"
   is partly the tuner learning to upweight the features the labels are made of.
2. **Win-model circularity.** Synthetic labels are generated by a linear logit over
   `FEATURE_COLUMNS` (`src/win_model/synthetic.py`), then a logistic regression is trained
   on the *same features* — the model recovers its own label generator, so ROC-AUC/Brier
   mostly measure sampling noise. Platt-scaling a logistic regression is also nearly a
   no-op (a sigmoid of a sigmoid).

The review also found **real-world matching gaps** (exact-string major/education-level
matching; unknown-amount scholarships filtered as ineligible) and **polish items**
(metrics module barely unit-tested, unpinned dependencies, hardcoded coverage badge,
102 committed eval reports, leftover internal docs).

This plan owns the *evaluation credibility + matching quality + hardening* track.
Fixing these turns the project from "impressive code" into a "defensible ML system."

## Design principles for this plan

1. **Honesty is the feature.** Where a metric has a known weakness, the fix is to measure
   it differently or disclose it prominently — never to hide it. Candid limitation notes
   are a portfolio differentiator.
2. **Protect behavior with tests before changing it.** The metrics module gets direct
   unit tests (Task 2) before any task that shifts ranking behavior (Tasks 4–5).
3. **Behavior changes require re-evaluation.** Any task that changes Stage 1/2/3 output
   ends with a fresh golden eval run and a README metrics refresh.
4. **Green gate every task.** `python -m pytest tests/ -q` stays green and
   `ruff check src/ scripts/ app/ tests/` stays at 0 errors after every task.

## Task 1: Evaluation Honesty — Cross-Heuristic Check + README Disclosure

**Why:** The cheapest defense against the proxy-label circularity critique: evaluate each
tuned config under the *other* label heuristic (`hybrid`-tuned weights scored with
`no_similarity` labels, and vice versa). If NDCG holds up cross-heuristic, the gains are
more believable; if it doesn't, that is worth knowing and saying. Also documents the
non-standard Coverage@k definition before someone mistakes it for an error.

**Preflight Files:**
- `scripts/evaluate_golden_students.py` (label-mode flag handling and report assembly)
- `src/eval/relevance.py` (`RelevanceConfig`, `proxy_relevance_labels`)
- `src/eval/metrics.py` (`coverage_at_k` at ~L57–88 — definition to document)
- `docs/evaluation.md` (existing honesty language to build on)
- `README.md` (Evaluation Results section)

**Validation Commands:**
```powershell
python -m pytest tests/ -q
ruff check src/ scripts/ app/ tests/
python scripts/evaluate_golden_students.py --k 10 --similarity-mode embeddings --cross-label-check
```

**Checklist:**
- [ ] Add a `--cross-label-check` flag to `evaluate_golden_students.py` that computes
      NDCG@k under BOTH label modes (`hybrid` and `no_similarity`) in one run and reports
      them side by side in the markdown report
- [ ] Add at least one test covering the cross-label report path
- [ ] Add a "Limitations & Evaluation Honesty" section to the README: proxy labels share
      features with the ranker (so tuned NDCG is partly self-fulfilling), the win model is
      synthetic, and the catalog is small — link to `docs/evaluation.md` for detail
- [ ] Document the Coverage@k definition (unique recommended / total recommended slots —
      a cross-profile diversity ratio, not catalog coverage) in the README metrics table
      footnote and in the `coverage_at_k` docstring
- [ ] Tests + ruff green

## Task 3: Human-Labeled Evaluation Set Harness

**Why:** The strongest answer to "your labels are circular" is a small human-judged test
set. Even ~100 hand-labeled (profile, scholarship) pairs turn proxy NDCG into a defensible
headline metric — and "I hand-labeled an eval set for my daughter's profile" is a great
interview line. This task builds the harness and worksheet; the actual labeling is a
human step done outside the task.

**Preflight Files:**
- `scripts/evaluate_golden_students.py` (where per-profile top-k lists and labels are built)
- `src/eval/relevance.py` (label semantics 0/1/2 the human labels must share)
- `src/eval/golden_students.py` (`nc_cs_rising_sophomore` — the primary labeling target)
- `.gitignore` (confirm `data/eval/` CSVs are NOT ignored — they should be committed)

**Validation Commands:**
```powershell
python -m pytest tests/ -q
ruff check src/ scripts/ app/ tests/
python scripts/make_labeling_worksheet.py --profile nc_cs_rising_sophomore --n 60
python scripts/evaluate_golden_students.py --k 10 --human-labels data/eval/human_labels_sample.csv
```

**Checklist:**
- [ ] Add `scripts/make_labeling_worksheet.py`: emits `data/eval/labeling_worksheet_<profile>.csv`
      with scholarship_id, title, sponsor, amount, deadline, description snippet, and an
      empty `label` column (0/1/2), sampled across the eligible set (not just the top-k,
      to avoid ranking bias in the label set)
- [ ] Add `--human-labels <csv>` to `evaluate_golden_students.py`: when provided, compute
      and report NDCG@k against human labels alongside proxy NDCG (rows without a human

- [ ] Commit a small `data/eval/human_labels_sample.csv` fixture (5–10 rows) so the path

- [ ] Add tests for worksheet generation and human-label NDCG computation

## Task 6: Win-Model Honesty — Calibration vs. Known Generator

**Why:** The win model currently *looks* like outcome prediction but is a linear model
recovering its own linear label generator. The defensible framing: a **calibration-pipeline
demonstration on a known generator** — show that predicted `p_win` recovers the true
latent `p_true` (which `synthetic.py` already stores in `meta_df`). Also address the
redundant Platt step honestly.

**Preflight Files:**
- `src/win_model/synthetic.py` (generator logits ~L154–165; `p_true` in `meta_df`)
- `src/win_model/train.py` (Platt calibrator ~L122–131; report payload ~L165–179)
- `docs/system_design.md` and `docs/evaluation.md` (win-model framing sections)
- `README.md` (Win Probability Model section)
- `tests/test_win_train_infer.py`

**Validation Commands:**
```powershell
python -m pytest tests/ -q
ruff check src/ scripts/ app/ tests/
```

**Checklist:**
- [ ] Extend `train_win_model` to evaluate against the known generator: hold `p_true`
      for the test split and report correlation + mean absolute error between predicted
      `p_win` and `p_true` in the training report JSON
- [ ] Add a "recovery check" section to the report: per-feature comparison of learned

- [ ] Reframe the README Win Probability section: this is a calibration/EV *pipeline

## Execution Order

```
1  Cross-heuristic check + disclosure  (cheap, pure addition — do first)
2  Metrics unit tests + API cleanup    (protects everything downstream)
3  Human-label harness                 (independent; human labeling happens async after)
4  Major taxonomy + level adjacency    (behavior change — after 2; re-eval at the end)
5  Unknown-amount handling             (behavior change — after 2; pairs with 4's re-eval)
6  Win-model honesty                   (independent of 4-5)
7  CI & reproducibility hardening      (any time; before 8 so CI guards the cleanup)
8  Repo curation                       (last — cosmetic, touches many paths)
```

Tasks 4 and 5 both shift eligibility sets; running them back-to-back means one combined
golden-eval re-run and one README metrics refresh instead of two.

## Success Criteria

1. The eval report shows NDCG under both label heuristics, and the README carries a
   "Limitations & Evaluation Honesty" section that names the proxy-label coupling.
2. `src/eval/metrics.py` has ≥ 90% direct test coverage and no `AssertionError`/`"N/A"`
   API warts.
3. A human-label workflow exists end-to-end: worksheet script → CSV → `--human-labels`
   NDCG in the report (with a committed sample fixture exercising it).
4. A CS student matches CE/STEM scholarships and a high-school profile matches
   undergraduate-labeled scholarships; strict mode restores old behavior; eligibility
   changes are re-evaluated and reflected in the README.
5. Unknown-amount scholarships pass Stage 1, rank on fit alone, and are flagged in the
   UI; stated-$0 records are still filtered.
6. The win model is framed (README + report) as a calibration demo that provably
   recovers its known generator's `p_true`.
7. CI enforces lint + tests + mypy + coverage ≥ 70 against pinned, reproducible deps,
   and the badge tells the truth.
8. A recruiter browsing the repo sees curated reports, no internal scratch docs, no
   foreign-project templates, and no `sys.path` hacks.
9. `python -m pytest tests/ -q` green and `ruff check src/ scripts/ app/ tests/` at
   0 errors after every task.
